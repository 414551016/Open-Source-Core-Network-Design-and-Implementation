## 工作目錄

- `pj3-dc/` 是課程作業庫的本機工作副本，程式變更位於 `free-ran-ue/`。
- `run-grade-with-captures.py` 從 VM 內的作業庫根目錄執行。它啟動原版 `test/grade.sh`，在每個 pcap 關閉時另存到上一層的 `evidence/`，避免兩種模式共用檔名。
- `render-captures.sh` 讀取 `/evidence` 中的 pcap，使用 TShark 顯示封包欄位，再擷取終端機畫面。

## 實作順序

1. 用既有 VirtualBox `free5GC` VM 準備 Go 1.26.2、Docker Compose、`gtp5g` 以及 workflow 指定的 golangci-lint v2.11.4。
2. 在 UE 和 gNB 模型接上 `ranDataPlanePort2`，再讓 UE 在同一條 N1 控制面連線建立兩個不同的 Session。
3. 保留 Session 4 的流程，將 Session 5 的 NAS Accept、TUN、UDP 連線、UL／DL TEID 各自保存。
4. 單 RAN 用 Master 的第二個 UDP 埠。雙 RAN 用 Xn 把 Session 5 的資料面交給 Secondary，並在 NGAP 回覆中回報 Secondary 的下行端點。
5. 跑官方評分腳本，依 UE 和 UPF 的擷取分別核對兩個方向。

## 封包截圖重現

原本的課程 VM 使用 `10.0.2.0/24` 的 VirtualBox NAT，與作業 Compose 的 UE 網段重疊。Compose 啟動後，宿主的 SSH 連線曾中斷。後續從既有課程快照另建 `free5GC-Project3-Test`，測試副本使用 `172.28.92.0/24` 的 NAT 與 1 vCPU，再從公開 fork clone 正式提交。原 VM 的 NAT 設定已恢復。

以下命令在測試副本的 `~/project3` 執行，前提是已從官方評分取得四份 pcap。

```bash
docker build -t pj3/pcap-evidence:local - < pcap-tools.Dockerfile
docker run --rm --network none --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v "$PWD/evidence:/evidence" -v "$PWD/render-captures.sh:/render.sh:ro" \
  pj3/pcap-evidence:local bash /render.sh
```
